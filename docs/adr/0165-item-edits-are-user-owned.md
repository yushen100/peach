# ADR-0165：编辑资料写下的值归用户，自动写入只补不覆盖

- 状态：已采纳
- 日期：2026-11-15
- 关系：沿用 [ADR-0034](0034-lone-community-source-fills-and-javdb-settles.md) 等确立的字段归属（`field_owners` 的 `user:manual` 最高）；补充 [ADR-0052](0052-entity-results-land-when-evidence-is-sufficient.md)：用户在界面上直接写下的断言不经复核，直接落库；实体合并留跳转见 [ADR-0088](0088-entity-merge-leaves-a-redirect.md)

## 背景

刮削给错、给缺或根本没有资料时，用户在界面上没有地方改：番号、标题、演员、厂牌、封面都只能靠重跑采集或手写 NFO。
`field_owners` 早就规定了「`user:*` 写下的字段自动写入者不得覆盖」，但只有批量改产地用到它；演员、标签落在
`asset_entity` 与 `asset_tag` 上，不归 `write_owned_fields` 管，厂牌、系列除了 `asset` 列还有实体关联，封面是数据根里的
一组文件。要做单片编辑，每一类都得说清楚用户这一笔写在哪、之后的自动写入会不会把它冲掉。

## 决策

**一、入口。** 详情标题旁的「编辑资料」一次改完字段、演员、厂牌、系列、标签和封面，点保存才写。字段写入带打开时读到的
`mutation_revision`，这期间后台改过这一部就整份拒收，不静默覆盖。侧栏标签改为只读；关注详情的标签在行尾「编辑标签」里增删。

**二、真相字段。** 番号、标题、原题、发行日期、产地、厂牌、系列走 `write_owned_fields(..., USER_MANUAL)`。「恢复」只清掉
这个字段的人工归属，现值留着等下一次采集替换；厂牌、系列同时把人工关联换成可被替换的 `legacy:asset` 关联。
自动写入厂牌、系列时，字段已归用户的那几部不挂刮来的实体关联，否则详情会并排出现两个厂牌。

**三、演员按人记录，不整组接管。** 用户加的人以 `user:manual` 来源写实体关联与 `performer:` 投影，刮削整组重写时本来就
不删这个来源。用户删的人真删这部片上的关联与投影，并记一条 `review_decision`：类别 `performer-removal`，键
`<资产 id>:<实体 id>`，状态 `rejected`。刮削落库整组重写演员之后、目录规则挂人之前都按这条决定再摘掉，所以删掉的人不随
采集回来，来源新补的人照常加上——和标签的单条隐藏是同一套规则。读取侧一律不用改。实体合并时决定改指保留的那一条。
用户再把这个人加回来就撤销这条决定。

不整组接管的理由：改过一次演员就不再接受来源补人，用户要么看不到后来补上的正确信息，要么得记得去点「恢复」，
而「恢复」会连同他删人、加人的改动一起丢掉。

**四、自建档案。** 搜不到时新建的演员、厂牌、系列，实体 `metadata_json` 记 `user_created: true`。刷新实体资料时所有类型都
保留 `user_` 开头的键，之后刮到同一个人也冲不掉这个标记。自建档案和刮来的放在同一个名册，界面上带随语言翻译的「自建」小标签；
不用图标，手势、符号的含义随地区不同。刮到另一种写法时按现有的合并并回。

**五、封面。** 用户给的图（上传、播放器当前画面、样张）转成 JPEG，经 `install_cover` 装成这一部的封面，`.scraping.json` 记
`source: user:manual`。`cover_settled` 认它为定稿，后台不再为它找封面；`install_cover` 拒绝自动来源覆盖它
（`UserCoverKept`），采集页的手动取封面也先跳过。第一次替换时原来那组文件挪进封面目录的 `.user-cover-originals/`，
「恢复刮削封面」放回去；连换几次，恢复的仍是刮削来的那张。封面按 `artwork_key` 存，同番号的版本、分卷共用。

**六、不在本次范围。** 文件改名、单片重抓与指定来源、标签分组自定义、多选批量编辑另行处理。

## 后果

- 用户改过的东西有了统一的保护规则：字段看 `field_owners`，演员看 `performer-removal` 决定，封面看边车来源。
- 新增的写入点只有四处要认这些规则：`_apply_performer_candidate`、`_apply_metadata_candidate` 的厂牌系列分支、
  `folder_rules._link`、`install_cover`。以后再加整组重写演员或装封面的路径，要接 `drop_removed_performers` 或
  经 `install_cover` 写。身份研究（`entity_identity_research`）是用户逐条确认的流程，暂不认删除决定。
- 不新增迁移：决定复用 `review_decision`，自建标记写在已有的 `metadata_json`，封面备份是数据根里的文件。
