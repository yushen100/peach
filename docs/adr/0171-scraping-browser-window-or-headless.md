# ADR-0171：后台采集浏览器分保留窗口与无窗口两种模式，都不抢前台

- 状态：已采纳
- 日期：2026-11-16
- 关系：修订 [ADR-0065](0065-cloudflare-sources-load-in-the-local-browser.md) 第二条「自动过不了就把窗口放回屏幕内并顶到前面」与「后果」第三条，以及「不用无头模式」一句；主动登录窗口沿用 [ADR-0093](0093-pikpak-browser-login.md)，不受影响
- 依据：#309 的反馈（验证窗口在用户干别的事时跳到前台）、社区 PR #310（后台采集一律用无窗口浏览器）

## 背景

ADR-0065 让 Cloudflare 后面的来源由本机浏览器取页：窗口平时在屏幕外，验证自动过不了时把窗口挪上屏并调
`Page.bringToFront` 顶到前面，等人点 `CLICK_SECONDS`（120 秒）。处理任务多在后台跑，用户正在打字、看片或开会时，
一个浏览器窗口突然抢走焦点；验证页上常常只是转圈、没有可点的框，弹出来也没用。

PR #310 的做法是后台采集一律 `--headless=new`，自动过不了就交给来源冷却。它解决了抢前台，但也去掉了人工点击这条退路：
有的站拒绝无窗口浏览器，有的出口被 Cloudflare 升级到要人点的那一档，这些情况下无窗口模式只能一直冷却。
两种取舍各有用户需要，由设置决定。

## 决策

**一、两种模式，按设置选，默认保留窗口。** 「来源与采集」里的「采集浏览器」一项选 `window`（保留窗口）或
`headless`（无窗口）。只影响后台采集用的浏览器。

**二、保留窗口模式：窗口始终在屏幕外，不自己上屏。** 自动阶段（清 Cookie 重载、`AUTO_SECONDS`）与 ADR-0065 相同。
自动过不了时登记 `browser_transport.attention()`（`/healthz` 带出去），再等 `CLICK_SECONDS` 让人点；窗口留在屏幕外，
不调整位置，不调 `Page.bringToFront`。用户从任务栏点开它时（屏幕外的窗口点任务栏只会被最小化，`minimized_by_user`
据此识别），Peach 才把窗口放回屏幕内给人点，过了或放弃都再最小化收起。`_unsolved` 照旧：同一站等过一次没人点，
之后撞验证到自动时限就报 `ChallengeUnsolved`，直到哪次页面正常打开；用户从任务栏点开时 `_unsolved` 里的站也照样等点击。

**三、无窗口模式：`--headless=new`，自动阶段过不了就冷却。** 不创建桌面窗口，没有人工点击这一段：重载后自动时限内
没过就清空验证页、报 `ChallengeUnsolved`，`SourceTransport` 按拒绝访问那一档冷却该来源，队列继续。
接受部分站点拒绝无窗口浏览器的代价，那时同样走冷却。

**四、主动登录不受影响。** 用户在界面上发起的浏览器登录（ADR-0093，眼下是 PikPak）由人主动打开，始终开在屏幕内并顶到前面，
与模式设置无关。

**五、模式按机器存。** 设置写在凭据根下 `scraping-browser.json`（`{"mode": "window" | "headless"}`），没设过或读不出来按
`window`。它描述这台机器上的浏览器行为，与 `browser/` profile 放在一起，不进账本、不随账本同步。浏览器每次拉起前读一遍；
运行中的浏览器模式与设置不一致时，下一条请求按新模式重开。

## 后果

- 后台采集不再在用户使用电脑时抢焦点；保留窗口模式下要人点的验证只在 `/healthz` 与任务栏里可见，没人点的话两分钟后这一站冷却。
- 无窗口模式省掉屏幕外窗口，但被拒绝无窗口浏览器的站与要人点的验证都只能等冷却到期。
- ADR-0065 第六条的 CDP 命令里 `Page.bringToFront` 只剩主动登录在用；认出用户从任务栏点开窗口另用 `Browser.getWindowBounds`。
