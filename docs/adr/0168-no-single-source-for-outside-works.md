# ADR-0168：库外作品的资料、资源与封面不只靠一家

- 状态：已采纳
- 日期：2026-11-16
- 关系：沿用 [ADR-0167](0167-less-reliance-on-javdb.md) 的「有替代就绕过 JavDB」；修订 [ADR-0068](0068-code-sample-images-group-the-photo-tab.md) 在线补样张的来源顺序；JavDB 图片仍只作复核证据（[ADR-0107](0107-cover-quality-and-javdb-evidence.md)）

## 背景

库内刮削按内容类型走多来源链，磁链查找有四个来源加后备索引器。2026-11-16 逐项盘点库外的取数功能，发现几处实际只有一家：

| 功能 | 原来的来源 | 缺口 |
| --- | --- | --- |
| 库外详情的资源面板 | 只有 JavDB（磁链区与评论链接） | 已有的磁链链没接上 |
| FC2 新作壳资料、想要清单资料 | 综合索引那一档，对 FC2 只剩 JavDB | FC2 五站链没接上 |
| 新作封面 | 只问官方渠道 | FC2、无码一家都没有，素人只有 MGS |
| 有码作品的官方样张 | 只有 DMM | r18.dev 有同一套原图 |
| 发现页资料补齐、库外详情资料 | 只有 JavDB | DMM、r18.dev 有大部分字段 |

同日 JavDB 账号被临时停用，这几处同时没有结果。

## 决策

**一、资源面板与想要清单同一份查询。** `/api/jav/resources` 改用 `wants_magnets.MagnetSearch`：manko、JavDB、sukebei、JavBus 四个磁链来源，
加 JavDB 评论里的 ed2k 与网页链接。同时只查一部，其余返回 busy，界面每 3 秒再取。

**二、FC2 新作壳先问 FC2 自己与存档站。** 依次问 FC2、fc2cmadb、JavArchive，取齐就不再问 JavDB。FC2PPV-DB、JAVten 要本机浏览器过验证，
后台取壳不弹验证窗口，不问。

**三、新作封面在 FC2、无码、素人与读不准的番号上补两处。** 带上发行方与存档站的图一起择优；官方仍落空时，取 AVBase、JavBus、JavDB
两个图源对得上的那张。JavDB 的图只参加比对，不装成封面。有码作品的官方渠道本来就有 r18.dev、DMM、Prestige 等几家，不加。

**四、有码样张 DMM 之后问 r18.dev。** 读 r18.dev combined 页的 `gallery[].image_full`，与 DMM 是同一套 `pics.dmm.co.jp` 原图；
本机 r18.dev 快照里的 gallery 也直接落。两站都说过没有，一周内不再问。

**五、JavDB 没答上时，有码作品的资料改问 DMM、r18.dev。** 发现页资料补齐与库外详情用退路资料填标题、发行日、厂牌、系列、时长、类别与演员；
没有评分、评论、样张与预告。退路资料不算 JavDB 答过，一天后重新排进待补；JavDB 冷却时补齐批次不再停下。

## 理由

- 这五处的替代来源都已接入，只是没接到这些功能上；改动只是复用现成的链。
- 退路资料不当作固定资料，JavDB 恢复后评分与精确类别还会补上。

## 后果

- 资源面板与想要清单共用一份缓存，同一部片在两处看到的资源相同。
- 资源面板的评论链接只查前 4 页（原来 8 页）。
- 无码、FC2 与素人作品的资料没有退路：DMM 与 r18.dev 不收这些作品。
- 仍只有一家的环节：评论（只有 JavDB）、按名字找演员与无码女优订阅（只有 JavDB）、库外演员头像（只有 JavDB，看过的有本地缓存）、
  创作者身份判定（seesaawiki）、事务所名册（minnano-av）、字幕搜索（SubtitleCat）；K-MIB、Babepedia 与各追更源按设计只有一家。
