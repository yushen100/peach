# 封面取景与边车契约

封面获取流程见 [JAV 封面技能](../.claude/skills/peach-jav-cover-workflow/SKILL.md)。本文件用于取景或边车任务；来源与算法实证见 [来源采集](SOURCING.md)，正式判据、阈值和版本在 `peach.jav_poster_crop` 与 `peach.face_detect`。

## 生产者与消费者

| 产物 | 生成入口 | 消费与保护 |
| --- | --- | --- |
| 人脸坐标 | `scripts/detect_cover_faces.py` | 保留归一化 `cx`、`cy` 和图像尺寸；裁切轴由容器比例决定，无脸时居中 |
| 正封边车 | `scripts/poster_crop_boxes.py`、`peach.jav_poster_crop` | 保存原图坐标和算法版本，原图保持完整；手工框不被自动重算覆盖 |
| 竖版正封 | `cover_artwork.install_cover`、`scripts/judge_cover_portraits.py` | DMM 竖版图与横图比对的结论记在正封边车的 `portrait`；独立海报不比横图矮时装到 `covers/front/`，边车记 `front` 尺寸，`/cover?front=1` 供卡片大图位 |
| 页面取景 | `frontend/src/card-art/framing.ts`、`frontend/src/jav-artwork.ts` | 复用边车和共享版式，不在页面抄写检测算法 |

默认仅重算缺失、版本过期、尺寸不符或不是按当前切点判据（`CROP_RULES`）算的产物，`--redo` 表示明确全算。

老用户升级后的存量封面由「设置 › 修复与迁移」的「已装封面的版式」一项自动补修（`peach.cover_repair`，三个脚本共用同一份逻辑）。它只改程序算出的值，所以按自动修复处理：服务起来几分钟后估算，有待处理的就在后台做，按任务中心的速度档逐张认字，中途停了下次启动接着做：
- 可能判错的番号封面补判竖版图，配信宣传图换成尺寸相近的 DVD 封套；没有来源记录的（2026-09 之前装的不记来源）按番号查 DMM。
- 边车没记当前 `CROP_RULES` 的重算切点。
- 取景判成整幅的在整张图里重找主脸和主体部位。

手工框与用户换的封面不动，改动前整组备份到升级修复目录。查过 DMM 却没有竖版图的（素人系）记下图片尺寸，不再算待处理。算法改变时同步版本、生产者与消费者，并验证旧边车的接收与重算；运行中服务需要切换时使用项目入口。

## 先分类再取景

DMM 的横图 `pl.jpg` 旁有竖版图 `ps.jpg`，即 FANZA 页面上的正封，固定从右缘量 0.703 倍高裁出。装 DMM 封面时一起取它，在横图里做模板匹配，先定这张封面属于哪一类：

| 类别 | 怎么认 | 怎么取景 |
| --- | --- | --- |
| 封套 | 竖版图在横图右缘逐像素对上（高清图要求 0.9 以上） | 在 DMM 左缘到它右边一个书脊宽内找折痕；找不到照 DMM 的切法（`match`） |
| 独立海报 | 竖版图对不上：VR、配信限定合集、SOD 双栏等另画的竖版图 | 横图整幅显示（`layout: still`）；竖版图不比横图矮时装成竖版正封，卡片大图位用它 |
| 整张照片 | 竖版图就是同比例的横图（素人系） | 横图整幅显示 |
| 没有竖版图 | 非 DMM 来源或取不到 | 走下面的折痕判据 |

分好类后，切点按下面的顺序定，前一条成立就不看后一条：

1. **书脊番号**（`peach.spine_label`）：在标准正封位置附近那条竖带里认番号，认出的那处就在书脊上，书脊右缘是它右侧第一道满高边。几何分不清书脊和正封里长得像书脊的竖排标题栏、闪粉框（NAMH-042、CEAD-731、JBS-016），书脊上印的番号分得清。认出并定下切点的番号框记进 sidecar 的 `spine`。框右缘往左的容差里只认明显的边（`LABEL_SLACK_COVERAGE`），书脊里照片的右缘常落在那里（MIDV-922）。测不出书脊右缘时（书脊与正封同色，VEC-789），原有判据的折痕与同前缀实测样本推出的吻合就用它，否则退回标准位置，并记 `spine_edge: false`，不拿来学模板。
2. **同模板封套**（`learn_templates`）：番号前缀与宽高比相同、已按书脊番号定了切点的封套至少两张且彼此一致，就按它们的正封宽高比切。800 宽的老图字太小认不出，同一家的大图认得出，书脊宽度是同一个。按厂牌、系列分组覆盖的封面大多也被前缀覆盖，没有接入。
3. **原有判据**：上表的 DMM 切法，或下面的折痕判据。

切点定下后再看一眼：没认出书脊番号、切线上却有至少两处横排大字横跨（`spine_label.count_across`，两边各伸出 4% 图高），说明那里没有书脊，整幅显示。MXDLP-318、SETBD-001、SGKX-016、STARS-532 是标准封套比例的整幅宣传图，几何和比例都拦不住，标题和宣传语拦得住；全库实测认出书脊番号的封套一张不中。竖排框不算：书脊上的竖排字常和正封竖排标题连成一个框。

文字识别复用人脸水印那份 PP-OCRv3 检测模型，加上同一来源 opencv_zoo 的 CRNN 英文识别模型，都走 OpenCV 自带的 dnn。模型和人脸模型一样随安装包与 Docker 镜像分发（`tools/face-models`，`scripts/fetch_face_models.py`）；源码运行没有随包那份时，装封面不自己下载，由补修与脚本开跑前取；没有模型时跳过第 1 条。VR 等整幅画面即使对上竖版图也不按封套切。

SOD 系的配信版横图是另画的双栏宣传图，择优统一用 DMM 的 DVD 封套，只有封套面积不到配信图一半（明显更糊）才用配信图（`jav_cover_fetch.PACKAGE_PREFERENCE`）。阈值与实测样本在 `peach.jav_poster_crop.portrait_match`。手工框优先于竖版正封。已装封面用 `judge_cover_portraits.py` 补判并按同一判据补换封套，默认只挑比例不标准、没找到折痕或判成整幅画面的，先在 `--covers` 指向的副本上试。

## 折痕判据

Sobel 列梯度寻找的是能切出合理正封形状的折痕，不按全宽固定百分比选最强边。窗口、突出度和形状阈值均读取源码常量。

- 厚书脊存在竞争峰时按正封形状选择，不按谁更强；代表回归为 ABP-968。
- 梯度斜坡的峰与终点分别处理；切点不满高时核对右侧满高接缝，避免把书脊文字边当折痕。ABW-147 覆盖文字边情形，TKM-005 对应已知黑边代价。
- 无满高缝时结合孤立尖峰、左右纹理方向和局部基线，避免切掉正封内容；IPZ-602、PPT-018 与 ABP-627 覆盖对应输入。
- 只有两侧接缝与纹理共同证明居中正封时裁中间；数字发行拼图、明确整幅图像与不满足判据的输入沿用当前版式判断。
- 宽封套结合来源、版次与图片比例，不仅凭接近 16:9 的外形判断。厂牌、比例窗口与例外以当前实现为准。
- 找不到折痕时，只有标准 DVD 封套比例按正封先验切；其余比例多是没有书脊的整幅图，整幅显示。比例不标准时找到的折痕还得满高（`RATIO_FOLD_COVERAGE`），4:3 与 SOD 1.416 的整幅宣传图里人物轮廓、大字也会被当成折痕。

## 页面投影与验收

框表达正封本身，页面容器负责最终比例和摆放，不在后端先裁成页面形状。传统正封完整居中，比例留白使用当前共享派生背景；整幅大封竖版按主体填满、横版完整显示，不使用模糊补边。手工框与明确整幅布局保留。

整幅大封的主体：正封取景判成整幅时，人脸在整张图里找，不再只看右侧正封（`cover_artwork.needs_whole_face`）。脸很小时，比主脸还大的身体部位记成人脸边车的 `subject`，卡片按它横向取景（`peach.body_parts`，NudeNet 320n 部位检测）。主打臀部、黑丝的 SDDE-613、STARS-080、AKDL-109 因此取到主体，不是角落里一张小脸。`face` 本身不变，换头像仍按脸截图。人体分割在拼贴图上几乎整张都标成人，没有采用。部位模型和书脊识别模型一样随安装包分发；已装封面由封面补修重找主脸和主体。

验证算法与前端投影时，同时检查人脸轴、图像尺寸、版本、正封边界和实际容器裁切。行为回归以 `tests/test_jav_poster_crop.py` 与前端卡片取景用例为准；通过坐标算术不能代替浏览器实际像素证据。
